# Project memory

## UI: clean and simple

The user explicitly prefers a clean interface without unnecessary labeling or clutter. Apply this preference to every tool and future UI change:

- Keep concise labels needed to identify actions, fields, data, and navigation.
- Do not add slogans, redundant explanations, repeated reassurance, or labels that merely restate nearby controls or values.
- Move secondary explanations into contextual native help. Use a small `questionmark.circle` help control when a visible affordance is useful, with information available on hover and an accessible keyboard/click equivalent.
- Give icon-only controls meaningful accessibility labels and useful native tooltips.
- Keep errors, partial results, and consequences of destructive actions visible when users need them to make a decision. Help is not a substitute for essential status or confirmation.
- Prefer removing unnecessary copy over adding new containers, badges, or information icons everywhere.

Preserve this preference when updating `PRODUCT.md`, `DESIGN.md`, and the design sidecar. Follow the existing native macOS design system rather than introducing a separate visual style.
